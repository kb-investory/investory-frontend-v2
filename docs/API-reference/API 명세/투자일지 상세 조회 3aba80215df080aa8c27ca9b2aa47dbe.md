# 투자일지 상세 조회

Method: GET
URL: /journal/entries/{journalId}
도메인: 투자일지

```
GET /journal/entries/{journalId}
```

`journalId`로 투자일지 상세를 조회합니다. 응답 구조는 2번 일자별 조회와 동일하며 조회 조건만 다릅니다.

# 요청 형식

## 요청 헤더

| 속성 | 자료형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `Authorization` | `string` | 필수 | `Bearer {accessToken}` 형식의 인증 토큰 |

## URL 파라미터

| 속성 | 자료형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `journalId` | `integer` | 필수 | 조회할 투자일지 식별자 |

예시 URL:

```
GET /journal/entries/305
```

## 쿼리 파라미터

## 속성 및 JSON Schema

- 2번 일자별 투자일지 조회와 동일
- 단, 3번은 존재하는 `journalId`를 조회하므로 `journal`이 `null`일 수 없음
- `canCreate`는 항상 `false`

## 구현 노트

```
-- 일자별 조회WHERE user_id= :userIdAND journal_date= :date-- ID별 상세 조회WHERE user_id= :userIdAND journal_id= :journalId
```

서비스 레이어의 상세 응답 조립 로직은 공유하고 조회 키만 다르게 처리합니다.

## 에러

### 존재하지 않거나 타인 소유인 경우

```
HTTP/1.1 404 Not Found
Content-Type: application/json
```

```json
{
  "code":"JOURNAL_NOT_FOUND",
  "message":"투자일지를 찾을 수 없습니다."
}
```

타인 소유 일지도 `403`이 아니라 `404`로 통일합니다.
