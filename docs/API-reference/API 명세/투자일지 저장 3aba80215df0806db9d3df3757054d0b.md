# 투자일지 저장

Method: POST
URL: /journal/entries
도메인: 투자일지

```
POST /journal/entries
```

시장에 대한 생각과 선택적으로 작성한 거래별 판단 근거를 함께 저장합니다.

# 요청 형식

## 요청 헤더

| 속성            | 자료형   | 필수 | 설명                                    |
| --------------- | -------- | ---- | --------------------------------------- |
| `Authorization` | `string` | 필수 | `Bearer {accessToken}` 형식의 인증 토큰 |
| `Content-Type`  | `string` | 필수 | `application/json`                      |

## URL 파라미터

- 없음

예시 URL:

```
POST /journal/entries
```

## 쿼리 파라미터

- 없음

## 요청 바디

```
{
  "journalDate":"2026-07-29",
  "marketThought":"반도체 업종의 상승 폭이 커 추격매수를 주의해야 한다.",
  "marketMood":"CAUTIOUS",
  "tradeNotes": [
    {
      "tradeId":501,
      "rationaleText":"HBM 시장의 장기 성장 가능성이 높다고 판단했다."
    }
  ]
}
```

## 속성

| 속성                         | 타입                       | 필수 | 설명                           |
| ---------------------------- | -------------------------- | ---- | ------------------------------ |
| `journalDate`                | `string(date)`             | O    | 일지 대상 날짜                 |
| `marketThought`              | `string`                   | O    | 시장을 보며 든 생각            |
| `marketMood`                 | `string(enum)` 또는 `null` | X    | 시장 감정                      |
| `tradeNotes`                 | `array`                    | X    | 판단 근거를 작성한 거래 목록   |
| `tradeNotes[].tradeId`       | `integer`                  | O    | 판단 근거를 연결할 거래 식별자 |
| `tradeNotes[].rationaleText` | `string`                   | O    | 해당 거래의 판단 근거          |

`tradeNotes`를 보내지 않거나 빈 배열을 보내면 거래별 판단 근거 없이 일지만 저장합니다.

# JSON Schema

```json
{
  "type": "object",
  "properties": {
    "journalDate": {
      "type": "string",
      "format": "date"
    },
    "marketThought": {
      "type": "string",
      "minLength": 1,
      "maxLength": 3000
    },
    "marketMood": {
      "type": ["string", "null"],
      "enum": ["CAUTIOUS", "CONFIDENT", "ANXIOUS", "CALM", null]
    },
    "tradeNotes": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "tradeId": {
            "type": "integer",
            "format": "int64"
          },
          "rationaleText": {
            "type": "string",
            "minLength": 1,
            "maxLength": 2000
          }
        },
        "required": ["tradeId", "rationaleText"]
      }
    }
  },
  "required": ["journalDate", "marketThought"]
}
```

# 응답 형식

## 응답 헤더

```
HTTP/1.1 201 Created
Content-Type: application/json
Location: /journal/entries/305
```

## 응답 바디

```
{
  "journalId":305,
  "createdAt":"2026-07-29T18:20:00+09:00"
}
```

## 속성

| 속성        | 타입                | 필수 | 설명                   |
| ----------- | ------------------- | ---- | ---------------------- |
| `journalId` | `integer`           | O    | 생성된 투자일지 식별자 |
| `createdAt` | `string(date-time)` | O    | 실제 생성 시각         |

# JSON Schema

```
{
  "type":"object",
  "properties": {
    "journalId": {
      "type":"integer",
      "format":"int64"
    },
    "createdAt": {
      "type":"string",
      "format":"date-time"
    }
  },
  "required": ["journalId","createdAt"
  ]
}
```

## 저장 검증

- 미래 날짜에는 작성할 수 없음
- 동일 사용자가 동일 날짜에 두 개의 일지를 작성할 수 없음
- `tradeId`는 로그인 사용자의 거래여야 함
- 거래 날짜와 `journalDate`가 같아야 함
- 요청 내 동일한 `tradeId`가 중복되면 안 됨

investment_journals INSERT

## 에러

### 동일 날짜에 일지가 있는 경우

```
{
  "code":"JOURNAL_ALREADY_EXISTS",
  "message":"해당 날짜의 투자일지가 이미 존재합니다."
}
```

### 미래 날짜인 경우

```
{
  "code":"JOURNAL_FUTURE_DATE_NOT_ALLOWED",
  "message":"미래 날짜의 투자일지는 작성할 수 없습니다."
}
```

### 거래 날짜가 일지 날짜와 다른 경우

```
{
  "code":"JOURNAL_TRADE_DATE_MISMATCH",
  "message":"일지 날짜와 거래 날짜가 일치하지 않습니다."
}
```
