# 투자일지 목록 조회

Method: GET
URL: /journal/entries
도메인: 투자일지

```
GET /journal/entries
```

캘린더 화면에서 일정 기간에 작성된 투자일지 목록을 조회합니다. 목록에서는 일지 본문과 거래 근거 원문을 전부 반환하지 않고 요약 정보만 반환합니다.

# 요청 형식

## 요청 헤더

| 속성 | 자료형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `Authorization` | `string` | 필수 | `Bearer {accessToken}` 형식의 인증 토큰 |

## URL 파라미터

- 없음

예시 URL:

```
GET /journal/entries?startDate=2026-07-01&endDate=2026-07-31
```

## 쿼리 파라미터

| 속성 | 자료형 | 필수 | 설명 |
| --- | --- | --- | --- |
| `startDate` | `string(date)` | 필수 | 조회 시작일 |
| `endDate` | `string(date)` | 필수 | 조회 종료일 |

## 요청 바디

- 없음

# 응답 형식

## 응답 헤더

```
HTTP/1.1 200 OK
Content-Type: application/json
```

## 응답 바디

```json
{
  "entries": [
    {
      "journalId":305,
      "journalDate":"2026-07-29",
      "marketMood":"CAUTIOUS",
      "tradeCount":3,
      "tradeNoteCount":2,
      "createdAt":"2026-07-29T18:20:00+09:00",
      "editableUntilAt":"2026-07-30T00:00:00+09:00",
      "isBackfilled":false,
      "isEditable":true
    }
  ]
}
```

## 속성

| 속성 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `entries` | `array` | O | 조회 기간 내 작성된 투자일지 목록 |
| `entries[].journalId` | `integer` | O | 투자일지 식별자 |
| `entries[].journalDate` | `string(date)` | O | 일지 대상 날짜 |
| `entries[].marketMood` | `string(enum)` 또는 `null` | O | 시장 감정. 입력하지 않았다면 `null` |
| `entries[].tradeCount` | `integer` | O | 해당 날짜에 발생한 전체 거래 수 |
| `entries[].tradeNoteCount` | `integer` | O | 판단 근거가 작성된 거래 수 |
| `entries[].createdAt` | `string(date-time)` | O | 실제 일지 작성 시각 |
| `entries[].editableUntilAt` | `string(date-time)` | O | 수정 가능 마감 시각 |
| `entries[].isBackfilled` | `boolean` | O | 과거 날짜의 일지를 뒤늦게 작성했는지 |
| `entries[].isEditable` | `boolean` | O | 현재 수정할 수 있는지 |

## 에러

- `400` — 조회 기간 형식이 올바르지 않은 경우
- `401` — 인증 토큰이 없거나 유효하지 않은 경우

# 공통 구현 기준

## 시간 계산

모든 날짜 계산은 한국 시간 기준으로 처리합니다.

```
ZoneId = Asia/Seoul
```

```
editableUntilAt
= 실제 일지를 생성한 날짜의 다음 날 00:00:00 KST

isEditable
= 현재 시각 < editableUntilAt

isBackfilled
= createdAt의 KST 날짜 > journalDate
```

## 소유권 검증

일지와 거래는 항상 로그인 사용자 기준으로 조회합니다.

```
WHERE user_id= :userId
```

타인의 일지·거래 ID를 요청한 경우에도 존재 여부를 노출하지 않도록 `404`를 반환합니다.

## 판단 근거 관리

거래 판단 근거는 별도 API로 생성·수정하지 않습니다.

```
POST /journal/entries
→ 일지와 근거 동시 생성

PUT /journal/entries/{journalId}
→ 일지와 근거 동시 수정·삭제
```

따라서 `journal_trade_notes`는 투자일지 저장·수정 서비스의 트랜잭션 안에서 관리하면 된다.
