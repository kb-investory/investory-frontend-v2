# OAuth 인증 완료

Method: GET
URL: /auth/oauth/{provider}/callback
도메인: 인증
상세 설명: OAuth 제공자가 전달한 인증 코드를 이용해 로그인·회원가입을 처리한다.

# 요청 형식

## 요청 헤더

- 없음

## URL 파라미터

| 속성       | 자료형   | 필수 | 설명                                            |
| ---------- | -------- | ---- | ----------------------------------------------- |
| `provider` | `string` | 필수 | OAuth 서비스 제공자. `KAKAO`, `GOOGLE`, `NAVER` |

## 쿼리 파라미터

| 속성                | 자료형   | 필수        | 설명                                                    |
| ------------------- | -------- | ----------- | ------------------------------------------------------- |
| `code`              | `string` | 조건부 필수 | OAuth 제공자가 발급한 인증 코드                         |
| `state`             | `string` | 필수        | 로그인 시작 요청과 콜백을 연결하는 검증값               |
| `error`             | `string` | 선택        | 사용자가 인증을 거절하거나 인증에 실패한 경우 오류 코드 |
| `error_description` | `string` | 선택        | OAuth 제공자가 전달한 오류 설명                         |

정상 콜백 예시:

```json
GET /auth/oauth/KAKAO/callback?code=abc123&state=state-value
```

인증 거절 예시:

```
GET /auth/oauth/KAKAO/callback?error=access_denied&state=state-value
```

## 요청 바디

- 없음

# 응답 형식

## 성공 응답

### 상태 코드

```json
302 Found
```

### 응답 헤더

Refresh Token을 HttpOnly 쿠키로 저장하는 구조를 추천한다.

```
Set-Cookie: refreshToken=eyJ...; HttpOnly; Secure; SameSite=Lax; Path=/auth; Max-Age=1209600
Location: https://investory.com/oauth/success
```

로컬 개발 환경에서는 `Secure`를 적용하면 HTTP에서 쿠키가 전달되지 않을 수 있으므로 개발·운영 설정을 구분해야 한다.

### 응답 바디

- 없음
- JSON Schema 없음

## 처리 과정

```
1. state 존재 여부 및 일치 여부 검증
2. 임시 저장한 PKCE code_verifier 조회
3. 인증 코드로 OAuth 제공자 토큰 요청
4. OAuth 제공자 사용자 정보 조회
5. social_provider + social_subject로 사용자 조회
6. 신규 사용자라면 users에 저장
7. Investory Access Token과 Refresh Token 발급
8. Refresh Token 저장 또는 갱신
9. Refresh Token을 HttpOnly 쿠키로 전달
10. 프론트 로그인 성공 화면으로 Redirect
```

OAuth 제공자가 전달한 콜백 URI는 사전에 등록된 URI와 정확히 연결되어야 하고, `state`는 요청 위조 방지를 위해 검증해야 한다.

## 실패 응답

콜백 API는 JSON 오류보다 프론트 실패 화면으로 리다이렉트하는 편이 자연스럽다.

### state 불일치

```json
302 Found
Location: https://investory.com/oauth/failure?reason=invalid_state
```

### 인증 코드 교환 실패

```json
302 Found
Location: https://investory.com/oauth/failure?reason=token_exchange_failed
```

### 사용자가 인증 거절

```json
302 Found
Location: https://investory.com/oauth/failure?reason=access_denied
```

오류 상세 메시지나 제공자 응답 원문은 URL에 그대로 노출하지 않는 게 좋다.
